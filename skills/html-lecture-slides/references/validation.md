# 검증 절차

1. 에셋과 글꼴을 모두 로딩한 실제 화면을 사용한다. HTML 문자열만 읽고 디자인 검증을 끝내지 않는다.
2. 모든 페이지의 스크린샷을 저장한다. 제목, 본문, 표의 긴 한국어 줄바꿈과 사진 크롭을 직접 확인한다.
3. 자동 검사 결과를 처리한다.
   - overflow: 화면 밖으로 나간 요소. 장식인지 확인한 뒤 위치·크기·페이지 분할로 해결한다.
   - text-clipped: 글자 줄 수에 비해 박스가 작다. 박스 높이, 내용 분할, 행간 순서로 검토한다.
   - missing-image / font-error: 파일 경로나 실제 로딩을 수정한다.
   - small-text: 강의실에서 읽을 수 있는지 판단한다. 출처 등 의도된 보조 글자만 예외 표시한다.
   - overlap: 중첩 디자인인지 오류인지 스크린샷에서 판단한다.
4. 표의 첫 행·마지막 행, 병합 셀, 긴 문장을 확인한다.
5. 영상은 metadata 로딩과 재생 시간 증가를 확인한다. 애니메이션은 초기·중간·후반 화면을 확인하고 콘솔 오류를 수집한다.
6. 편집기에서 한 요소를 수정하고 내보낸 HTML을 새 문맥에서 연다. 새 문맥에서 이미지·글꼴·영상과 이전/다음 이동을 확인한다.
7. 내보낸 HTML을 편집기에 다시 불러와 편집 정보가 유지되는지 확인한다.

검사 보고서에는 검사한 파일, 페이지 수, 실행한 검사, 수정 내용, 남은 경고와 외부 의존성을 기록한다. 자동 도구가 감지하지 못하는 시각적 문제를 숨기지 않는다. 인터넷이 필요한 결과는 오프라인 검증과 구분한다.
